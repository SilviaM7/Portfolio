# Data dictionary

All nine files are **synthetic**, generated by `scripts/generate-data.ts` with seed `20260930`. `npm run check:data` fails if a committed file differs from a fresh generation. Names of providers, models, products, teams, and every price or rate are fictional. Patterns were seeded on purpose to demonstrate methods; they are not empirical findings.

General rules for every file:

- Dates are `YYYY-MM-DD` and months `YYYY-MM`, with no time zone.
- Money is in US dollars.
- **Blank means unknown.** A blank value is never read as zero. Each file below states what happens to blank values.
- Rows that cannot be used are dropped at the validation boundary (`src/projects/<id>/schema.ts`) and counted by reason. Each project page shows these counts in its data-quality table.

## AI Spend & Consumption (`public/data/ai-spend/`)

### `usage_events.csv`

**Grain:** one row per model request. **Key:** `request_id`. **Rows:** 4,736. **Period:** 2026-01-01 to 2026-09-30.

| Column | Type / unit | Meaning and rules |
|---|---|---|
| `request_id` | text | Unique request key. Duplicates are dropped; the first row is kept. |
| `event_date` | date | Request date. It selects the price in force that day. |
| `department` | text | One of 6 departments. Joins to `department_budgets.department`. |
| `use_case` | text | One of 12 business use cases. |
| `provider`, `model` | text | 3 fictional providers, 5 models. `model` joins to `model_pricing.model`. |
| `input_tokens` | integer, tokens | **Total** prompt tokens. This total includes `cached_input_tokens`. |
| `cached_input_tokens` | integer, tokens | The part of `input_tokens` billed at the cached rate. If it exceeds `input_tokens`, the row is flagged and excluded from spend. |
| `output_tokens` | integer, tokens | Generated tokens. Partial output on failed requests is billed as recorded (an assumption). |
| `status` | `success` / `failed` | Outcome of this request. |
| `latency_ms` | integer, ms | Blank means not recorded. The row stays in spend and counts but is excluded from latency statistics. |
| `retry_of_request_id` | text | The earlier request this one retries. Blank means a first attempt. |
| `task_id` | text | Shared by all attempts at one piece of work. |
| `task_outcome` | `completed` / `abandoned` | `completed` if any attempt succeeded, otherwise `abandoned`. |

### `model_pricing.csv`

**Grain:** one row per model and price period. **Key:** `model` + `effective_from`. **Rows:** 7.

| Column | Type / unit | Meaning and rules |
|---|---|---|
| `model`, `provider` | text | Model and its provider. |
| `effective_from`, `effective_to` | date | Validity period. A blank `effective_to` means the price is still in force. |
| `input_usd_per_mtok`, `cached_input_usd_per_mtok`, `output_usd_per_mtok` | USD per 1,000,000 tokens | Token prices. |
| `price_basis` | text | Always `fictional assumption`. These are not real vendor prices. |

A request dated before its model's first `effective_from` cannot be priced. It is excluded from spend and counted, never priced at $0.

### `department_budgets.csv`

**Grain:** one row per month and department. **Key:** `month` + `department`. **Rows:** 72. **Period:** 2026-01 to 2026-12.

| Column | Type / unit | Meaning |
|---|---|---|
| `month` | month | Budget month. Months after September have no actuals and are used only next to the projection. |
| `department` | text | Joins to `usage_events.department`. |
| `budget_usd` | USD per month | Departmental budget. |

**Seeded patterns and issues (Spend):**

- Seeded anomalies:
  - a retry storm in Marketing "Campaign analysis", 2026-05-12 to 2026-05-14;
  - a quarter-end Finance close;
  - an oversized-context batch job in Engineering "Code assistance" on 2026-07-14.
- Seeded data-quality issues:
  - 9 requests dated before their model's first price;
  - 6 rows with more cached tokens than input tokens;
  - 14 blank latencies;
  - 8 exact duplicate request ids.

## AI Adoption & License Utilization (`public/data/ai-adoption/`)

### `license_assignments.csv`

**Grain:** one row per seat assignment. **Key:** `assignment_id`. **Rows:** 613. **Assigned dates:** 2025-10-01 to 2026-08-28.

| Column | Type / unit | Meaning and rules |
|---|---|---|
| `assignment_id` | text | Unique key. Duplicates are dropped; the first row is kept. |
| `employee_id` | text | Pseudonymous id (`E0001`…). Contains no personal data. Joins to `product_activity` together with `product`. |
| `department`, `product` | text | Seat holder's department and the licensed product. They join to `department_eligibility` and `contracts`. |
| `assigned_date` | date | An administrative assignment date, not the date the person first used the product. |
| `unassigned_date` | date | Blank means still assigned. If it is earlier than `assigned_date`, the row is dropped. |

### `product_activity.csv`

**Grain:** one row per employee, product, and week. **Key:** `employee_id` + `product` + `week_start`. **Rows:** 6,695. **Weeks:** 2026-07-06 to 2026-09-21 (12 weeks).

| Column | Type / unit | Meaning and rules |
|---|---|---|
| `week_start` | date (Monday) | Telemetry week. A date that is not a Monday is dropped. |
| `active_days` | integer 0–7 | Days with at least one action. **Blank means telemetry was not reported**. It is not read as 0 active days, and the seat-week is left out of weekly denominators. |
| `actions` | integer | Product actions in the week. This is a usage signal, not a measure of value. |

### `department_eligibility.csv`

**Grain:** one row per department and product. **Key:** `department` + `product`. **Rows:** 21.

| Column | Type / unit | Meaning |
|---|---|---|
| `department_headcount` | people | Employees in the department. |
| `eligible_employees` | people | How many employees the policy allows a seat for. A row is dropped if this exceeds headcount. |

### `contracts.csv`

**Grain:** one row per product. **Key:** `product`. **Rows:** 3.

| Column | Type / unit | Meaning |
|---|---|---|
| `seat_price_usd_per_month` | USD per seat per month | List seat price (fictional). |
| `committed_seats` | seats | Seats paid for in the current term. |
| `term_start`, `renewal_date` | date | Current term. The commitment can change only at renewal. |
| `notice_days` | days | Notice required before renewal to change the commitment. |
| `floor_seats_at_renewal` | seats | The minimum commitment allowed at renewal. |
| `price_basis` | text | Always `fictional assumption`. |

**Seeded patterns and issues (Adoption):**

- Seeded patterns:
  - bulk assignment waves with lower engagement (Atlas Assistant 2026-04, Scribe Meetings 2026-05);
  - two Marketing employees holding Forge Code seats although Marketing has 0 eligible employees.
- Seeded data-quality issues:
  - a Scribe Meetings telemetry outage in the week of 2026-07-20, with blank values rather than zeros;
  - 6 activity rows dated before the seat was assigned (trial use, excluded from seat status);
  - 4 overlapping duplicate assignments;
  - 3 impossible date ranges.

## AI Workflow Value & Quality (`public/data/ai-workflow/`)

### `workflow_records.csv`

**Grain:** one row per completed task. **Key:** `task_id`. **Rows:** 1,188. **Period:** 2026-01 to 2026-09. The pilot (AI-assisted work) runs from 2026-04.

| Column | Type / unit | Meaning and rules |
|---|---|---|
| `task_id` | text | Unique key. Duplicates are dropped; the first row is kept. |
| `month` | month | Completion month. |
| `workflow` | text | One of 3 business workflows. |
| `complexity` | `low` / `medium` / `high` | Task complexity. |
| `team` | text | Teams A and B are pilot teams, because they used AI-assisted work at some point. Team C is the comparison team and never did. |
| `process` | `baseline` / `ai_assisted` | How the task was done. |
| `handling_minutes`, `review_minutes` | minutes | Hands-on and reviewer time. Blank, negative, or implausible values make the row unusable, and it is dropped. |
| `rework_minutes` | minutes | **Blank means not recorded.** The row is kept but excluded from time and cost metrics, never counted as 0 rework. |
| `quality_outcome` | `pass` / `fail` | **Blank means not audited.** The row is excluded from pass rate and cost per successful task. |
| `escalated` | `yes` / `no` | Whether the task needed senior staff. |

### `cost_assumptions.csv`

**Grain:** one row per assumption. **Key:** `parameter`. **Rows:** 6. Every `basis` is `fictional assumption`.

| `parameter` | Unit |
|---|---|
| `labor_rate_usd_per_hour` | USD per hour (fully loaded) |
| `ai_variable_cost_usd_per_task` | USD per AI-assisted task |
| `escalation_cost_usd_per_task` | USD per escalated task |
| `ai_software_usd_per_month` | USD per month |
| `implementation_one_time_usd` | USD, one-time |
| `training_one_time_usd` | USD, one-time |

If any parameter is missing or invalid, the whole file is rejected with a message naming it. The page does not silently fall back to defaults.

**Seeded patterns and issues (Workflow):**

- Seeded patterns:
  - a learning curve in the early pilot months, fading by the fourth month;
  - an easier task mix for volunteer Team A, which is a selection effect.
- Seeded data-quality issues:
  - 11 blank quality outcomes;
  - 5 blank rework values.
